# SSE streaming wire format

The chat endpoint `POST /api/chat/stream` returns an HTTP `200` with `Content-Type: text/event-stream` and an AG-UI-shaped event stream. The frontend's `useChatStream` hook (`frontend/src/hooks/useChatStream.js`) consumes it.

## Why SSE and not WebSocket?

- One-way (server → client) is enough — the client only sends the request body.
- Plays well with HTTP/1.1 reverse proxies (nginx, Cloudflare).
- Auto-reconnects aren't needed (we use `fetch` + `AbortController` from the SPA).
- Trivially debuggable in `curl` / browser DevTools.

## Headers

```
Content-Type: text/event-stream
Cache-Control: no-cache
Connection: keep-alive
X-Accel-Buffering: no       # disable nginx buffering
```

## Event envelope

Every line in the stream is a single SSE `data:` line, terminated by a blank line (`\n\n`):

```
data: {"type": "RUN_STARTED", "run_id": "abc...", "conversation_id": "..."}\n\n
data: {"type": "TOOL_CALL_START", "tool_call_id": "...", "tool_name": "search_documents"}\n\n
data: {"type": "TOOL_CALL_END", "tool_call_id": "...", "status": "ok", ...}\n\n
data: {"type": "TEXT_MESSAGE_START", "message_id": "...", "role": "assistant"}\n\n
data: {"type": "TEXT_MESSAGE_CONTENT", "message_id": "...", "delta": "The "}\n\n
data: {"type": "TEXT_MESSAGE_CONTENT", "message_id": "...", "delta": "revenue "}\n\n
data: {"type": "TEXT_MESSAGE_CONTENT", "message_id": "...", "delta": "is ..."}\n\n
data: {"type": "TEXT_MESSAGE_END", "message_id": "...", "citations": [...], "used_tools": [...]}\n\n
data: {"type": "RUN_FINISHED", "run_id": "...", "finish_reason": "stop"}\n\n
```

The wire format is generated by `app/services/llm/streamer.py` (one `sse(event, payload)` helper that produces a `bytes` literal).

## Event reference

| Event | Payload | When |
|---|---|---|
| `RUN_STARTED` | `run_id`, `conversation_id` | First event of every turn. |
| `TOOL_CALL_START` | `tool_call_id`, `tool_name` | Before the orchestrator executes a tool. |
| `TOOL_CALL_ARGS` | `tool_call_id`, `arguments` | Optional — the resolved arguments. |
| `TOOL_CALL_END` | `tool_call_id`, `result`, `status`, `latency_ms` | After the tool returns. |
| `TEXT_MESSAGE_START` | `message_id`, `role` | Right before the answer deltas. |
| `TEXT_MESSAGE_CONTENT` | `message_id`, `delta` | One per streamed delta (32 chars in the Phase 1 chunker). |
| `TEXT_MESSAGE_END` | `message_id`, `citations`, `used_tools` | After the final delta. Includes the citation list (chunk ids the LLM cited). |
| `RUN_FINISHED` | `run_id`, `finish_reason` | Successful end. |
| `RUN_ERROR` | `run_id`, `error` | On any unhandled exception. The session is rolled back; the user sees a graceful message. |

## Event boundaries

The wire format uses `\n\n` as the boundary (RFC 8895 / WHATWG SSE spec). Some proxies (notably older nginx) may emit `\r\n\r\n` instead, so the frontend parser handles both — see the `splitBlocks` function in `useChatStream.js`.

## Cancellation

The frontend passes an `AbortController` signal to `fetch`. When the user navigates away, the controller is aborted, the `ReadableStream` is closed, the backend's StreamingResponse is torn down (FastAPI's `event_iter()` exits), and the session is rolled back if no commit has happened yet.

## Debugging

```bash
TOKEN="<paste access_token here>"
curl -N -X POST http://localhost:8000/api/chat/stream \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"message": "What is the revenue in Q2?", "conversation_id": null}'
```

`-N` disables curl's output buffering so you can see events as they arrive.
